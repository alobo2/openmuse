### Hostile review of prior work

### Finding 1 — Multimodal tool results could stay in Rich Threads after sanitization failed

- **Issue:** `textOnlyToolResult` only stripped image/binary parts when JSON parsed into TanStack content parts. Malformed JSON or a non-part array left the raw string (including base64 image payloads) on the AG-UI tool result, defeating the thread-storage guard.
- **Fix:** On parse failure or invalid part arrays, replace content with a short fixed message instead of returning the event unchanged.
- **Test:** `tests/tool-result-thread.test.ts` — malformed `[`… payload, valid multimodal strip, invalid array shape, plain text unchanged.

### Finding 2 — Scheduled `refreshIdeas` failures were invisible in logs

- **Issue:** `maintain()` caught `refreshIdeas` errors and sent an in-app notification but did not call `backgroundFailure`, so operators had no structured log line for the underlying error (unlike other maintenance paths).
- **Fix:** Pass the error to `backgroundFailure("refresh ideas", error)` before notifying.
- **Test:** `tests/workflows.test.ts` — stub `workspace.snapshot` to throw; assert notification title and logged `context.phase === "refresh ideas"`.

### Finding 3 — Leading whitespace bypassed multimodal thread sanitization

- **Issue:** `textOnlyToolResult` used `content.startsWith("[")` on the raw AG-UI string. Encoders that pretty-print or indent JSON often prefix whitespace, so the guard never ran and binary image data stayed in stored thread history.
- **Fix:** `trimStart()` before the `[` check and `JSON.parse`, leaving non-JSON plain text unchanged.
- **Test:** `tests/tool-result-thread.test.ts` — `"  "` + multimodal parts JSON strips the image and keeps text only.

### Finding 4 — Thread sanitization mistook plain `[` text and generic JSON arrays for multimodal leaks

- **Issue:** After `JSON.parse` failed, `textOnlyToolResult` always substituted the omission message whenever the trimmed content started with `[`, corrupting legitimate bracketed prose. After a successful parse, any non–`ContentPart` array received the same substitution, even when the payload was ordinary structured JSON with no `type` fields (no image or binary parts to strip).
- **Fix:** On parse failure, substitute only when the payload looks like a TanStack parts array (`[` then `{`). On successful parse, substitute only when every array element is an object with a string `type` (multimodal-shaped) but fails `isContentPartArray` validation.
- **Test:** `tests/tool-result-thread.test.ts` — `[Meeting notes] …` unchanged; `[1,2,3]` unchanged; existing malformed `[{"type":"image"…` cases still omit binary data.
